# LLVC 语音转换对照实验

这份网页演示围绕两个问题展开：端侧主算法 LLVC 与项目内的 RVC、QuickVC 对比算法，在同一台 CPU 上能否跟上实时输入？给它们同一句语音，更换模型、处理模式或音高配置后，输出听起来有什么变化？

| 演示内容 | 可以看到或听到什么 |
| --- | --- |
| 算法与模型 | 三条推理链分别如何提取内容、使用音高和合成语音，以及 11 个转换权重编号与算法、文件、目标音色的对应关系。 |
| 处理速度 | 20 组 CPU 实测 RTF，按同一配置并列比较流式与非流式。结合 LLVC 的 13 ms 块和 RVC、QuickVC 的 100 ms 块，查看每块计算是否赶得上下一个输入块。 |
| 成对试听 | 用同一句话比较三种算法、三套 LLVC 权重、RVC 带 F0 与无 F0 的路径、不同目标音色，以及同一音色的索引比例 0 与 0.75。中英日语料和男女输入可用于复听。 |

可[在线查看演示](https://nicriverhoo.github.io/llvc_presentation/)，也可打开同目录的 [index.html](index.html) 离线播放。离线分发时保留本目录及 `audio/` 的完整内容。

进入试听后，选择一组语料。同一列比较的是同一输入，每种配置均可试听流式与非流式。点击“原音”可随时回听输入。播放器支持拖动进度；勾选“同一输入沿用播放位置”可在一句话中途切换配置，取消勾选则从头播放。不同输入始终从头开始。

本次试听包含 10 个原音与 164 个不同输出，均取自 2026-11-19 至 20 日完成的四批文件转换。RTF 使用单独的六段性能测试输入。试听文件名中的性别标记沿用输入，音轨的目标性别和移调按运行配置展示。
